## Changes and evidence

The effective resolver returns the original baseline object for OFF, SHADOW,
resolved PAGE_LAYOUT and every Dynamic resolution fallback. It adds no resolution
ID, uiContext, warnings or effective field attributes to those outputs. Internal
UUID correlation remains in P7, with `usedForAgent=false`. Only ENFORCE with
DYNAMIC_FORMS or supported, validated MIXED and no fallback returns the effective
fields, uiContext and matching uiContextResolutionId (`usedForAgent=true`).

Draft semantic validation moved out of the legacy executor into the extra-work
boundary. OFF ignores it. SHADOW catches it and returns the exact baseline.
ENFORCE preserves structured invalid-draft errors. Classification uses the actual
validation stage, not just the ContextRuntimeError class: a ContextRuntimeError
from snapshot infrastructure is still a Dynamic resolution failure and fallback.
Original object/Record Type/identity/ObjectInfo/CreateDefaults/Picklist failures
remain original failures, and tests compare their entire Tool error results.

The extra-work boundary covers USER enrichment, snapshot read/parse, App discovery,
active page resolution, draft validation, visibility and field aggregation.
Audit exceptions and rejected Audit promises are observational. No retry, queue,
new correlation store, provider or cross-request state was introduced. Resolver
version is `P8-04.2`; parser and persisted JSON schema remain `P8-04.1`.

The Host no longer infers missing resolution evidence from an absent Agent-visible
ID for ready CREATE. Its selection/UPDATE/error evidence path remains available.
HTTP regression verifies one UI_CONTEXT resolution event per successful context
call and prevents falsely labeling ready Page Layout as Record Type selection.
Admin displays `usedForAgent`, `snapshotWarning` and failure category alongside
the existing ID, snapshot hash/timestamp and Lightning Page evidence.

`create_record.uiContextResolutionId` remains optional and unverified client
provenance. The HTTP test follows an actual Dynamic context ID into UI_CONTEXT_LINK
and verifies the submitted Salesforce DML payload contains only the original fields
and RecordTypeId. No DML implementation changed. Canonical Playbook 1.6.0 already
says “when supplied” and “If absent, creation still follows the existing workflow”;

### Layout human-readable identity: PAGE_LAYOUT_FULL_NAME_DEFERRED

The runtime's reliable identity is the Layout ID returned by current USER Create
Defaults. A-01 proved exact ID matches by separate targeted Tooling Layout queries
(`scripts/p8-04a-feasibility.mjs`, LayoutIdentity path); it did not populate the
production current snapshot with that mapping. Current refresh retrieves
CustomObject, CustomApplication, Profile, Record Type and referenced FlexiPage
facts. These do not provide a reliable Layout ID → fullName mapping.

Reusing a Lightning Page name or Profile assignment label would invent identity.
A targeted runtime Layout lookup would add an API call to the protected legacy
path; an org-wide Metadata Layout listing would add an inventory outside this
closure. No such lookup/inventory was added. Audit retains authoritative Layout ID
and known Lightning Page fullName. Human-readable Layout identity remains a
documented limitation, as permitted by the HOTFIX complexity gate.

### Latency and snapshot behavior

Previously USER getUserInfo, snapshot and App reads each had a separate 3s wait,
allowing a slow chain to approach 9s. They now share one 3s extra-read deadline.
Expired budgets do not start the next read; timed-out operations cannot publish a
late effective result. This is a read budget, not a server cancellation guarantee
or an independent HTTP request deadline. No scheduling/cache/workers were added.

Latency measurements use in-memory USER/snapshot integration fixtures, 10 warm-ups
and 100 measured Shadow resolver calls. They measure extra resolution work only,
not Salesforce network/MySQL latency or real Agent performance. Measured extra
work: **p50 0.8491 ms / p95 3.8412 ms**. The never-settling USER test returned
legacy after approximately 3016 ms. Live p50/p95 remains a real UAT measurement.

Manual refresh/current-only retention is unchanged. Tests confirm stale READY,
FAILED and REFRESHING snapshots record SNAPSHOT_STALE, refreshedAt and hash while
SHADOW output stays legacy. Malformed old snapshots safely fall back; snapshot
metadata is retained in Audit even when parsing fails.
