# 适用查重：业务身份与事件

CREATE 用当前对象的业务身份/事件键发现可能已存在的同一记录；UPDATE 仅在实际改变适用身份值时检查并排除目标自身。查重是 Agent 侧判断，不是 DML Token、服务器审批或新的唯一性引擎，Salesforce Duplicate Rules 仍是最终裁决。

## 选择有意义的键

从当前对象字段 label/help/type、可取得的 unique/externalId 与任务语义判断。名称、电话、手机、邮箱、统一社会信用代码、外部 ID 都可能有用，但强度取决于业务：共享电话、家庭邮箱和同名只证明候选，不能直接判定同一主体。

不是每个字段都要查重。备注、描述、金额、阶段、默认值、managed 值不例行检查；普通关联查询命中客户，是关系解析，不是新拜访重复。事件记录结合客户、日期/时间及事件含义；同客户历史有拜访不阻止另一次来访。没有适用键记为 NO_IDENTITY_VALUE，不额外追问身份字段或遍历整张表。批内重复也要按同一业务/事件语义判断，不能把共用联系方式直接合并。

## 有界查询与真实覆盖

优先复用已取得且仍适用的 USER 数据；需要新查时用当前允许的 `query_records` 与小的 maxRows，或合法的 `run_soql_query`。只投影 Id、展示字段和判定所需键；查询条件中的值正确转义，不能成为 SOQL 语法。当前字段是否可过滤以 metadata/实际返回为准，错误不通过猜字段反复重试。

输入标准化不证明 Salesforce 存储文本也标准化。电话保留国家码语义：`+1` 不能按大陆 `+86` 去除。可先查询已知的原始形式与合法规范形式；存储可能含空格、括号或连字符时，有界获取由其他有区分度的键缩小的候选，再逐项规范比较。`LIKE '%完整数字%'` 不能覆盖数字间有分隔符的文本，不能假称该查询已全面查重。无可靠缩小条件时说明未覆盖的存储形式，不全表扫描或伪造唯一。

0 行是 NO_MATCH_OBSERVED：仅当前 USER 共享/权限范围与已查询条件下未找到，不证明全库唯一。LIMIT、truncated、totalSize/returnedCount 和游标决定覆盖；查询带 LIMIT 时 totalSize 也不能证明原始全集。查询失败/字段不可查/工具不可用是 CHECK_INCOMPLETE，说明具体限制；不能将它变成所有 CREATE 的固定批准门槛。与实际提交正确性有关的关键歧义才需解决。

## 候选与业务选择

普通的初始“新建”只是动作意图，不代表用户已经知晓后来发现的同记录证据并决定再建一份。用已有材料先判断是否确为独立事件；仍指向同一业务记录且选择未解决时，保存前集中询问。用户已知匹配事实并明确要求另建独立记录时，直接按该决定执行。

| 证据 | 处理 |
| --- | --- |
| 只有同名、共享电话或模糊候选 | 用客户主体、时间、地址角色或其他已知事实收窄；不能取第一条，也不自动要求批准所有候选 |
| 同客户、不同时间/事件 | 可按新事件创建；历史记录不是本次重复 |
| 实质证据指向同一业务记录，仍有冲突/选择 | 告知匹配事实，集中询问继续新建 / 改为更新 / 取消；已有选择不再问 |
| 0 行、无适用键、部分或失败查询 | 准确限定证据；无其他实质歧义时继续已授权任务，不能声称没有重复 |

**MUST NOT** 静默将 CREATE 改为 UPDATE、自动合并或隐瞒实际同记录冲突。用户明确“补充刚才那条”时复用已证明目标；明确“即使疑似重复仍新建”时报告适用查重结果后继续，不重复批准。改为更新仍须唯一目标和 minimal patch，不能猜 ID。批量将仍影响正确性的选择集中询问，保持每项结果和授权范围。
