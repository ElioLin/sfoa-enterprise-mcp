# 时间对齐：异常时间点 × 变更时间线

「昨天下午开始就不对了」是诊断里最常见、也最有用的一句话。它有锚：**异常起点**。没有锚的时候，任何一条变更记录看起来都像嫌疑人；有锚之后，嫌疑人通常减少到个位数。

所以默认第一步不是去读配置，而是**把锚问出来**，再把变更排到同一条时间线上。

## 第一步：问出异常起点

要问到的三件事，缺哪件就补哪件：

1. **最早一次观察到异常是什么时候**（不是「发现」的时候，是「最早出现」的时候）。
2. **在那之前最后一次确认正常是什么时候**（下界。有了上下界才能框住窗口，否则「之前最近的一条变更」可能是几周前那条）。
3. **是所有人/所有记录都这样，还是只有一部分**（影响面决定了窗口要开多大、要不要按用户分节看）。

用户只能给出模糊时间（「大概上周」）也可以开工——把窗口开成「上周 + 之前一段」并**在结论里说明窗口就是这么定的**。窗口定得粗不是问题，装作定得细才是。

## 第二步：一次调用拿合并时间线

`get_platform_diagnostics` 用覆盖「异常起点**及其之前一段平静期**」的窗口，返回按时间合并的证据条目，每条带来源节标识。窗口里必须有平静期，否则条目全挤在窗口边缘，你无法判断哪条与起点相邻。

读时间线的顺序：

1. **从异常起点向前看，不向后看。** 起点之后的条目解释不了「从那时起变坏」。
2. **取起点之前最近的一条**，读出它的来源节、动作、操作者、时间。
3. **再看往前若干条**，判断是否只有这一条与症状语义相关；如果有若干条，按 [evidence-and-citations.md](evidence-and-citations.md) 的强度排序，而不是按时间远近。
4. **对候选条目二次取证**：变更类 → 用 `get_metadata_component_context` 读被改组件的定义；失败类 → 转代码类路径。时间线负责**定位候选**，不负责**证明因果**。

**时间线只由读到的那些节拼成。** 某一节不可用时，它的条目**根本不在这条线上**——所以「起点之前没有变更」这句话，只有在**变更那一节确实读到了**的前提下才成立。回答时要先报每一节的状态，再说时间线上看到了什么；把一条缺了一节的时间线当作完整时间线，是这类诊断最常见的假阳性来源。

## 第三步：把「相关」写成「相关」

时间相邻是**候选**，不是结论。要升级成因果，还差一条：**被改的那个东西，语义上能解释这个症状**。

- 「09-30 14:12 有人改了校验规则 `X__c`，异常从 14:20 开始」= 相关性 + 时间吻合，**仍是候选**。
- 加上「读了 `X__c` 的定义，它的条件正好拦住了这批记录」= 因果成立。

只做到第一步就下结论，是把相关性当因果——这是诊断里最贵的错误，因为它会让用户去改一个本来没问题的东西。

## 时钟域

不同来源的时间戳不一定在同一个时钟上：Salesforce 侧生成的时间、诊断工具所在主机的调用时刻、以及各存储层自己的时间，可能来自不同的时钟域，彼此有偏移。

因此：

- **不要**把跨来源的时间戳直接相减来算「多久之后发生的」，也不要直接排序后当作先后。需要比较时，优先在**同一来源内部**比较（同一张表的两行、同一次返回里的两个字段）。
- 需要跨来源对齐时，把**精度要求降下来**：分钟级的位置关系通常仍然可靠，秒级的因果链不可靠。结论里就写到分钟级，不要写「3 秒后触发」。
- 窗口的边界是**工具自己声明的窗口**，不是你以为的窗口。回答里带上窗口的起止，而不是只说「最近」。

## 窗口与保留边界

证据都有保留边界，且保留策略通常**不通过查询暴露**。因此：

- 窗口 **MUST** 按证据自身的边界陈述：读到了多少条、最旧一条是什么时候。这是**被测量的界**。平台聚合类工具会把「该来源现存最旧一行」作为字段交给你，用它，不要自己估。
- **MUST NOT** 假定一个「大约 N 天/月」的常数，并据此宣布「那个时间点之前没有记录」。窗口够不到异常起点时，如实说够不到。
- 窗口够不到时的补救：**收窄问题**（只问最近发生的同类异常）、**换证据源**（改走不依赖窗口的静态路径，见 [decision-tree.md](decision-tree.md) 的代码类「不可复现」分支），或者**如实报告无法回溯**。最后这条是合格答案。
- 计数也要按同一标准：某一节说「0 条」时，要能看出这是**在真实数据上跑过并匹配为零**，还是**读不到**。工具会为此提供独立的证据（例如该来源的状态取值清单、该节自带的读/不可用状态）；只有前者才支持「那段时间没有该类事件」。

## 某节不可用时

合并时间线的价值在于「一条线」，但某一节读不到时，**不要**退化成一句「时间线正常」：

- 说清**哪一节读到了什么**（条目数、窗口）。
- 说清**哪一节不可用、缺哪个前提**。
- 说清**缺了它，这次对齐还能不能支持结论**——如果关键的一节（例如变更溯源）正好不可用，那么「起点之前没有变更」这句话**不成立**，必须明说这次对齐是残缺的。
