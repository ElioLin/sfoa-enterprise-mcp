# 适用日志与新 Trace

TraceFlag 只记录开启后实际发生的执行，不能追溯历史。这不表示历史日志不存在：先通过当前可用 get_apex_logs / get_debug_log_body 找到并复用时间、主体、执行入口都适用的现有日志，避免机械开 Trace、重复复现和轮询。

确需新日志、现有证据不足且 set_trace_flag 已启用时，按当前 Schema 选择真实实体与 durationMinutes 窗口；向用户给出最短复现步骤和业务前提，等待窗口内实际执行，再读取对应日志。开启成功只证明设置已接受，不证明已经执行或日志就绪。生效延迟、窗口、权限和日志保留都可能造成空结果；先核对实际执行和时间，不机械要求用户反复提交可能有副作用的业务动作。

不能复现时，仍可利用当前错误、异步失败、变更、元数据、权限归因等授权内证据继续调查，不强制任何单一路线。日志是证据之一。缺失、不可用或截断要说明对结论的限制，不按「空日志=正常」或「开 Trace=已拿到日志」汇报。

需要重新开启或清理 Trace 时只按当前工具真实能力处理，不编造删除工具、不换身份、不把诊断扩成业务写入。用户明确要求技术细节才在正文展开类名和日志行；内部始终保留可追溯原始证据。
