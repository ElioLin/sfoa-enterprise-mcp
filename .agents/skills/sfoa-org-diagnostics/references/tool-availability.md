# 工具可用性：没有这个 Tool 时该说什么

诊断工具是**默认关闭、按路由逐个启用**的。同一个会话里，六个诊断 Tool 可能只启用了一部分，甚至一个都没有。这不是故障，是治理：谁在什么场景下能拿到多大的诊断面，由 Admin 按路由决定。

因此「工具不在」是**正常状态之一**，必须有一条明确的应对方式。

## 先判断是「没启用」还是「没权限」

| 观察到的 | 含义 | 应对 |
| --- | --- | --- |
| Tool 根本不在当前连接的能力清单里 | 该路由**没有启用**它 | 告诉用户：这个诊断需要 Admin 启用该 Tool，并说清启用后能回答什么 |
| Tool 在，但调用被拒绝（结构化错误） | 已启用，但**当前身份/前提不满足** | 原样转述缺失的前提；不要换目标反复试 |
| Tool 在、可用，但结果里某一节不可用 | 该 Tool 的**某个来源**读不到 | 按 [degradation-and-indeterminate.md](degradation-and-indeterminate.md) 逐节转述 |

结构化错误里带一个**缺失前提标识**（一个可被引用的短标签，或一句被测量的约束描述）。**MUST** 连同错误码一起原样转述：它是用户去找我们补前提时的钥匙，改写成自然语言会让复核断线。

**只看能力清单，不要猜。** 不要因为「这个 Tool 应该存在」就去调它；也不要因为一次调用失败就断言「整个诊断能力不可用」。

## 缺工具时，结论停在哪一步

缺一个 Tool 不等于诊断结束，但**必须说清停在哪**。写法是三句：

1. **已经确认了什么**（用可用的 Tool 拿到的证据，照常引用）。
2. **哪一步没法走**（缺哪个 Tool、它本来是这一步的唯一确定性路径）。
3. **所以要谁做什么**：请 Admin 为该路由启用该 Tool；或（用户接受时）在证据强度更低的前提下继续。

> 「前两步已经可以确认：该组件在 09-30 被修改过，且修改者与报告的时间吻合。第三步读它的定义需要 `get_metadata_component_context`，当前连接上不可用——所以「定义里哪一段导致了这个症状」我**没有证据**。请让 Admin 为该路由启用该 Tool，我可以在启用后一次读完。」

**MUST NOT** 把「缺工具」写成「没有发现问题」。缺口就是缺口。

## 不要手拼长查询替代确定性工具

`run_diagnostic_tooling_query` 是一条**原始只读诊断查询**通道。它的存在不构成替代路径，理由有三个：

1. **它绕过了为该问题设计的判据**。确定性工具（权限归因、组件上下文、平台时间线）内含语义与降级契约；一条手写查询没有，结论会退化成「我读到了这些行，你自己看」。
2. **它的证据强度更低**。手写查询的结果不携带工具级的语义声明（哪些节读到了、哪些判据不可解析），因此更容易被误读成完整答案。
3. **它扩大的是使用面而不是能力面**。每一次绕过都在把「没有这个能力」悄悄改写成「用别的方式凑出来」，下一轮就没人知道缺的是哪个 Tool 了。

规则：

- **默认**：缺工具时按上面的三句写法停下。
- **例外**：用户**明确要求**一次临时深挖（「先用手写查询看一下」）时可以做，但 **MUST** 同时声明：这是**临时路径**，不是该问题的确定性工具；结论的证据强度弱于确定性工具；以及缺口仍然存在。
- **MUST NOT** 自作主张地把手写查询当作常规替代——尤其是当用户并没有要求、只是想问一个问题的时候。

## 部分启用时，不要点名未启用的工具

只启用了一部分诊断 Tool 时，回答里 **MUST NOT** 把未启用的 Tool 名字当作下一步建议丢给用户，好像它可用一样。正确做法是**描述要走的下一步**，让用户/Admin 决定要不要启用：

- ✗ 「接下来我会用 `explain_field_access` 查一下权限来源。」（它没启用，这句话是空头承诺）
- ✓ 「下一步需要做字段级权限归因（哪条简档/权限集给了这个字段的可见性）。这一能力在当前连接上不可用，需要 Admin 为先启用。」

同一条规则适用于**工具自己给出的提示**：如果一个 Tool 的返回里提到另一个 Tool，而那个 Tool 并不在本次连接的能力清单里，那么那句话对这次会话不成立——按「缺工具」处理，不要把它当下一步执行。

## 启用之后

Admin 启用后，能力清单会变。**MUST** 以**当前**清单为准，而不是记住的清单：

- 上一轮不可用的 Tool，这一轮可能已经可用；反之亦然。
- 一段对话里能力发生变化时，**重新确认**清单，不要假设它没变。
- 需要跨多轮才能走完的诊断（例如「开 trace → 等复现 → 读日志」），在继续之前确认每一步需要的 Tool 仍然可用；中途消失时按缺工具处理，并说明诊断停在哪一步。
